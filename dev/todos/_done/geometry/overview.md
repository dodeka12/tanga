# Geometry Submodule — Overview Plan

**Goal:** Create a new `py/pytanga/geometry/` submodule that provides algebra-independent
data classes for geometric entities and operators, plus analysis functions to extract
geometric meaning from multivectors/blades. This enables the user to easily create multivectors
from geometric entity descriptions and also to analyze what geometry or operator a multivector
represents.

---

## 1. Submodule Structure

```
py/pytanga/geometry/
├── __init__.py              # Re-exports all public symbols
├── entities.py              # Algebra-independent geometric entity data classes
├── operators.py             # Algebra-independent operator data classes
├── analysis.py              # Top-level analysis dispatcher
├── analysis_e3.py           # E3-specific analysis functions
├── analysis_p3.py           # P3-specific analysis functions
├── analysis_pga3.py         # PGA3-specific analysis (projective, single null vector)
├── analysis_n3.py           # N3-specific analysis (full conformal, two null vectors)
├── create.py                # Top-level creation dispatcher
├── create_e3.py             # E3-specific creation
├── create_p3.py             # P3-specific creation
├── create_pga3.py           # PGA3-specific creation
└── create_n3.py             # N3-specific creation
```

## 2. What Already Exists (Foundation)

The `py/pytanga/basis/` submodule provides algebra-specific classes that know about
named blades, entity masks, and factory methods:

| Algebra | Python Class | C++ Class | Signature | Null Vectors |
|---------|-------------|-----------|-----------|-------------|
| Euclidean 3D | `BasisE3` | `CBasisE3` | G(3, 0) | — |
| Projective 3D | `BasisP3` | `CBasisP3` | G(4, 0) | — |
| Null 3D (CGA) | `BasisN3` | `CBasisN3` | G(5, 0b10000) | `einf` + `eo` |
| PGA 3D | `BasisPGA3` | — (extends `BasisN3`) | G(5, 0b10000) | `einf` (uses only the sub-algebra with one null vector) |

### 2.1 N3 vs PGA3 — Critical Distinction

`BasisN3` and `BasisPGA3` share the same C++ basis (`CBasisN3`, dim=5, sig=0b10000)
and the same Python class hierarchy (`BasisPGA3` extends `BasisN3`). However, they
represent **different geometric models**:

| | N3 (Full Conformal) | PGA3 (Projective Sub-algebra) |
|---|---|---|
| **Null vectors** | both `einf` and `eo` | only `einf` |
| **Geometric model** | Conformal Geometric Algebra | Projective Geometric Algebra |
| **Point embedding** | `x·e1 + y·e2 + z·e3 + α·ep + β·em` | `x·e1 + y·e2 + z·e3 + α·einf` (no eo component) |
| **Entities** | Point, PointPair, Line, Circle, Plane, Sphere, Space | Point, Direction, Line, Plane, Space |
| **Operators** | Reflection, Inversion, Rotor, Translator, Dilator, GeneralDilator, Motor, GeneralRotor | Reflection, Rotor, Translator, Motor |

The reason for the embedding is described in `docs/py/basis/pga_null_embedding.md`:
a null vector like `einf` (which squares to zero) cannot be represented in a metric
Clifford algebra with only ±1 squares. It is embedded as `einf = ep + em` where
`ep² = +1`, `em² = -1`. The full CGA uses both `einf = ep + em` and `eo = 0.5·em - 0.5·ep`.

**PGA3** is a sub-algebra of N3 that only spans the subspace generated by
`{e1, e2, e3, einf}` — it does **not** use `eo`. This means entities like
circles, spheres, and point pairs (which depend on the full conformal structure)
are **not available** in PGA3. Operators like inversion and dilation are also
N3-only.

**Detection strategy:** Since `BasisPGA3` extends `BasisN3` and they share the same
algebra signature, the dispatcher uses `isinstance(alg, BasisPGA3)` to detect PGA3
(checked before `BasisN3`, since `BasisPGA3` is a subclass). If the algebra is `BasisN3`
but not `BasisPGA3`, it is treated as full N3/CGA.

## 3. Design Principles

1. **Algebra independence:** `entities.py` and `operators.py` use plain Python data
   classes (`dataclasses.dataclass`) with no dependency on `pytanga.algebra`, `pytanga.MV`,
   or any specific basis class. They can be created from and converted to MVs, but they
   are not MVs themselves.

2. **Single dispatcher:** The `analysis.py` function `analyze(mv)` determines the
   algebra type of a given multivector (or list of multivectors) and delegates to
   algebra-specific analysis functions in `analysis_e3.py`, `analysis_p3.py`, or
   `analysis_pga3.py`.

3. **Two-way conversion:** Each analysis module provides both:
   - `analyze(mv) → Entity/Operator` — extract geometric meaning from an MV
   - Factory functions like `make_point(algebra, x, y, z) → MV` — construct an MV
     from geometric parameters (these may live on the basis classes themselves, but
     the analysis modules can provide helper wrappers)

4. **IPNS representation:** By default, entities are assumed to be in the Inner Product
   Null Space (IPNS) representation, which is the natural representation for CGA/PGA.
   OPNS representation may be supported with an optional parameter.

5. **Decomposition pipeline:** The analysis workflow is:
   ```
   MV/BladeMask → Determine algebra → Identify entity/operator type → Factorize blade/versor → Extract parameters → Return dataclass
   ```

6. **Uses existing factorize algorithms:** Entity decomposition uses the existing
   `blade_factorize()` method (backed by C++ `FactorizeBlade()`) to obtain the
   grade-1 factor vectors of a blade. Operator decomposition uses
   `blade_factorize_versor()` (backed by C++ `FactorizeVersor()`) to obtain
   the scale and factor vectors. These factor vectors directly correspond to
   geometric parameters (points, direction vectors, normals, etc.).

## 6. Entity × Algebra Coverage Matrix

| Entity | E3 | P3 | PGA3 | N3 | Notes |
|--------|:--:|:--:|:----:|:--:|-------|
| Point | ✓ | ✓ | ✓ | ✓ | Grade 1 everywhere but different basis composition |
| Direction | — | ✓ | ✓ | ✓ | Ideal point at infinity (not in E3) |
| Point Pair | — | — | — | ✓ | Grade 2, full N3 only (needs eo) |
| Line | — | ✓ | ✓ | ✓ | Grade 2 in P3, grade 3 in PGA3/N3 |
| Circle | — | — | — | ✓ | Grade 3, full N3 only (needs eo) |
| Plane | ✓ | ✓ | ✓ | ✓ | Grade 2(E3), 3(P3), 4(PGA3/N3) |
| Sphere | — | — | — | ✓ | Grade 4, full N3 only (needs eo) |
| Space | ✓ | ✓ | ✓ | ✓ | Top-grade pseudoscalar |

> **PGA3 is a sub-algebra of N3** using only the subspace generated by
> `{e1, e2, e3, einf}`. Entities that require `eo` (PointPair, Circle,
> Sphere) are **N3-only**. The `Direction` type exists in PGA3 and N3
> but not in E3.

## 7. Operator × Algebra Coverage Matrix

| Operator | E3 | P3 | PGA3 | N3 | Notes |
|----------|:--:|:--:|:----:|:--:|-------|
| Reflection | ✓ | ✓ | ✓ | ✓ | Grade 1 vector |
| Inversion | — | — | — | ✓ | Grade 1, full N3 only (needs eo) |
| Rotor | ✓ | ✓ | ✓ | ✓ | Scalar + bivector (E3/P3: e12,e31,e23; N3: same subspace) |
| Translator | — | — | ✓ | ✓ | Scalar + ei-bivectors |
| Dilator | — | — | — | ✓ | Scalar + E, full N3 only (needs E = einf∧eo) |
| General Dilator | — | — | — | ✓ | Scalar + ei + E, full N3 only |
| Motor | — | — | ✓ | ✓ | Rotor × Translator |
| General Rotor | — | — | — | ✓ | Rotor + ei-bivectors, full N3 only |

> PGA3 operators are a subset of N3 operators. Dilator and its variants
> require the `eo` null vector and are N3-only. PGA3 supports the motor
> (rotation + translation) but not general rotor or dilator variants.

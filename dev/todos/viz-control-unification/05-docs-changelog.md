# Phase 5 — Docs, examples, changelog

## Goal

Update the public docs and examples to describe the single control system, and
record the change in a branch changelog per `dev/workflows/changelog.md`.

## Files

- Edit: `docs/py/viz/interaction/controls.md`
- Edit: `docs/py/viz/interaction/control-views.md`
- Edit: `docs/dev/architecture/viz-controls-and-interactions.md`
- New: `docs/changelog/YYYY-MM-DD_feat-view-architecture.md`
- Edit: `docs/py/examples/viz/interaction/all_controls.md` (if it uses `add_*`)

## Steps

- [ ] **5.1 — Architecture doc (`viz-controls-and-interactions.md`)**
  - Document that there is a single control path: `*View` classes serialized via
    `view_layout`; `add_*` is a facade over `*View` into an implicit overlay
    `GroupView`; the `controls_define` orphan-panel path is removed.

- [ ] **5.2 — Reference docs (`controls.md` / `control-views.md`)**
  - Fold the `add_*` reference into `control-views.md` (or cross-link) so
    `add_slider` ↔ `SliderView` show identical parameters, including
    `on_press` / `on_release` and `variant`.
  - Remove references to the `controls_define` panel path.

- [ ] **5.3 — Examples**
  - Update any `add_*` examples whose behavior changed; verify examples still run.

- [ ] **5.4 — Changelog**
  - Run `uv run python tools/last-release.py` for the since-relative title.
  - Create `docs/changelog/YYYY-MM-DD_feat-view-architecture.md` with the
    Refactor/Breaking/New-Features sections per `dev/workflows/changelog.md`.
    - Breaking: the legacy `controls_define` panel-control path is removed.
    - New Features: `SliderView`/`add_slider` `on_press`/`on_release`;
      `add_slider`/`add_button`/`add_checkbox` `variant`.
